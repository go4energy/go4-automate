# Audit & Strategie — go4-automate
> **Datum:** 2026-04-26
> **Scope:** Vollständige Plattform-Review + strategischer Plan für die Positionierung als "Marketing & Sales OS"
> **Methodik:** 4 parallele Audit-Pässe (Modul-Struktur, Frontend, DB-Schema, Bugs/Security) + 1 strategischer Pass (Markt/Positionierung). Keine Code-Änderungen vorgenommen.

---

## TL;DR

go4-automate ist eine **technisch solide, ~70 % verkaufsreife Plattform** mit unverwechselbaren Differentiators (DSGVO-konformes Lead-Scraping via Serper, integrierte Engagement-KI, Self-Hostbar). Vor dem Verkauf fehlen aber **fünf kritische Bausteine**:
1. **Payment-Integration** (Stripe) — sonst kein Self-Service-SaaS möglich
2. **Reporting-Dashboard** — KPIs sind verstreut, kein ROI-Proof
3. **Demo-Daten / Onboarding** — neue Tenants sind leer
4. **Multi-Tenant-Hardening** — `ondelete=CASCADE` fehlt auf Tenant-FKs in Contacts/LinkedIn (Datenleck-Risiko)
5. **Reporting + Public API** — Voraussetzung für Integrationspartner

Die Code-Basis ist konsistent (100 % `<script setup>`, alle Stores im Setup-Style, FastAPI/Vue-Patterns sauber), zwei Module sind allerdings übergewichtig (assistant 2.933 Z., engagement 1.942 Z.) und 105+ `datetime.utcnow()`-Aufrufe brechen in Python 3.13.

**Empfehlung:** 90-Tage-Plan mit 3 Phasen: Managed Service starten (Wochen 1–4) → Self-Hosted für Agenturen (Wochen 5–8) → SaaS mit Stripe (Wochen 9–12).

**Pattern-Drift im Error-Handling:** Engagement (152 HTTPException-Aufrufe), Funnels (75), Briefing (88) wrappen `AppError` redundant zu `HTTPException` im Router. Leadgen ist die Referenz: `AppError` propagiert, globaler Handler in `main.py:184-191` macht die Konversion. **Fix:** In Router je Modul `raise e` statt `raise HTTPException(status_code=e.status_code, detail=e.message)`.

## 1.3 DB-Schema (Score 7/10)

70 Migrations, davon 3 als Hash-Branches (LinkedIn merge-trail, sollten linearisiert werden).

**🔴 Kritisch — Tenant-FK ohne `ondelete='CASCADE'`:**
- `contacts.tenant_id` (`models.py:24`) → Orphans bei Tenant-Löschung
- 5 LinkedIn-Tabellen (`linkedin_accounts`, `linkedin_scraper_jobs`, `linkedin_contacts`, `linkedin_messages`, `linkedin_connections`) — Default ist `RESTRICT`, Tenant-Löschung scheitert
- **Aufwand Fix:** 2 Migrations (`071_fix_company_tenant_fk.py`, `072_fix_linkedin_tenant_fks.py`)

**🟢 Tenant-Scoping korrekt:** Alle UNIQUE-Constraints sind tenant-scoped (z.B. `uq_leadgen_campaign_slug(tenant_id, slug)`). Kein globaler Slug-Clash möglich.

**🟡 Status-Indexe ohne tenant_id:** `assistant_actions`, `conversion_events`, `assistant_drafts` haben Single-Column-Status-Indexe, das verursacht Cross-Tenant-Scans bei Filter `WHERE status='pending'`. **Fix:** Composite `(tenant_id, status)`.

**🟡 JSONB-Anti-Patterns:**
- `tags` in 16+ Tabellen (collector_groups, briefing_sources, etc.) — keine Constraints, Duplikate
- `streams` in 14+ Tabellen — sollte FK zu `streams`-Tabelle
- `metadata_json` / `raw_*_json` (assistant) — kann zu MB+ wachsen, kein Indexing
- `session_data` (linkedin_accounts) — OAuth-Tokens im Backup, kein Revocation-Tracking
- `stage_state` (leadgen_runs) — durch unsere Timeline-Doku jetzt strukturierter, aber resume-state-Felder noch frei

## 1.4 Bugs / Security (Score 7/10)

**🔴 Sicherheits-Risiken:**
1. **Encryption-Plaintext-Fallback**: `emailmarketing/encryption.py:26-29` und `whatsapp/encryption.py:26-29` — wenn `EMAIL_ENCRYPTION_KEY` nicht gesetzt, werden API-Keys **unverschlüsselt** in DB gelegt. **Fix:** Environment-Validation in `config.py`, Exception werfen statt Fallback.
2. **Hardcoded Dev-IPs in CORS**: `main.py:102-106` — `192.168.1.227` und Localhost im Code. **Fix:** `settings.local_dev_origins`.

**🟠 Funktionale Bugs:**
3. **CRM ohne user_id im Audit-Trail**: `crm/router.py:621,736` — `ActivityService.create(tenant_id, None, data)` → keine User-Zuordnung in Activities/Tasks.
4. **Surveys hardcoded URL**: `surveys/router.py:311,340` — `base_url="https://app.go4-automate.com"` statt `settings.app_url`.
5. **Stille Startup-Warnings**: `main.py:51,67,86` — Admin/Prompt-Seeding-Fehler werden ignoriert statt zu brechen.

**🟡 Tech-Debt:**
- **105+ `datetime.utcnow()` Aufrufe** (deprecated in Python 3.13). Top: emailmarketing/* (18), linkedin/* (24), engagement/* (12). **Fix:** Sed-Migration zu `datetime.now(UTC)` (~4h).
- **5 TODO/FIXME** im Code, davon 4 mit Produktiv-Impact.
- **2 print() in CLI-Tools** (encryption.py) — sollten `logger.info`.

**🟢 Was gut läuft:**
- 0 SQL-Injection-Findings (alle Queries parameterisiert)
- 0 `eval()` / `exec()` / `subprocess shell=True`
- Kein `requests` (überall `httpx`)
- CORS korrekt allowlisted (kein `["*"]`)
- 95 % Type-Hint-Coverage

**🔴 Test-Lücken:**
- `crm/service.py` (627 LoC) — kein eigener Test
- `whatsapp/service.py` (1.050 LoC) — minimal
- `funnels/service.py` (~900 LoC) — nicht gezielt getestet

## 2.2 Fünf größte Produkt-Lücken vor Launch

### Lücke 1 — Payment-Integration (kritisch, blockierend)
- Status: nicht implementiert
- Impact: ohne Stripe/Paddle keine Self-Service-SaaS möglich
- Fehlt: Billing-Engine (Usage-Tracking, Invoice-Gen, Dunning), Subscription-Mgmt, Tenant-Provisioning, Multi-Currency
- Erster Schritt: `app/billing/service.py` + Stripe Webhooks + Tenant-Customer-Mapping
- Aufwand: 4 Wochen (1 FS-Engineer)

### Lücke 2 — Reporting / KPI-Dashboard
- Status: KPIs sind pro Modul verstreut, kein Cross-Module-Dashboard
- Impact: B2B-Buyer wollen ROI-Proof in 30 s
- Fehlt: Materialized Views, Recharts-Frontend, CSV/PDF-Export, BI-Anbindung (Looker / Metabase)
- Erster Schritt: 5-KPI-Dashboard (Leads/Mo, Cost/Lead, Email-Open-Rate, Pipeline-Value, Engagement-Rate)
- Aufwand: 4 Wochen

### Lücke 3 — Onboarding / Demo-Daten
- Status: Setup-Wizard funktioniert, leerer Workspace nach Sign-up
- Impact: ~80 % User-Churn in Woche 1 (branchentypisch wenn keine Demo-Daten da)
- Fehlt: Auto-Seed-Workspace mit 5–10 Fixtures (Contacts, Pipeline, Engagement, Sample-Email-Template)
- Erster Schritt: `seed_demo_workspace()` Function + Hook bei Tenant-Erstellung
- Aufwand: 2 Wochen

### Lücke 4 — Multi-User-Rollen + Audit-Log
- Status: User/Group-Model existiert, Permission-Matrix nicht enforced
- Impact: Frontend hat nur binär Admin/User → keine Rollen "Sales Manager", "Content Lead"
- Fehlt: Row-Level-Security-Audit, `require_permission()` Decorator, AuditLog-Modell, Per-Module-Permission-Schema
- Erster Schritt: Lint-Tool für "missing tenant_id checks", fix Top 5 critical services
- Aufwand: 6 Wochen (incremental)

### Lücke 5 — Public API + Marketplace
- Status: nur interne API, keine OAuth2-Dev-Keys, kein Zapier/Make-Connector
- Impact: Integration-Partner können nicht andocken
- Fehlt: OpenAPI-Schema (vorhanden, aber nicht öffentlich), API-Versioning, OAuth2 Dev Apps, Webhook-Store
- Erster Schritt: `app/api/v1/public/*` Routes + OAuth2 Authorization-Code-Flow
- Aufwand: 4 Wochen

4. **"Selbstgehostete Marketing-Automation"**
   _Docker-Compose, Hetzner-VPS, deine Daten bleiben deine. No vendor lock-in._
   Beweis: vorhandene Docker-Infra + Caddy-HTTPS.

5. **"Wetter-optimierte Werbe-Kampagnen"** (Energy-Vertical-Spezial)
   _PV-Anfragen peaken bei Sonnenschein. Wir boosten dein Ad-Budget automatisch._
   Beweis: Ads-Modul + Meta-CAPI-Integration. **Unique** — keine Konkurrenz hat das.
